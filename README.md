# ContentLoom

Portfolio reference implementation of a 2025 project, built to show a product-copy generation pipeline at catalog scale. Thousands of SKUs and three locales go in; drafts are generated by Claude, scored automatically, and either published or routed to a human reviewer.

**Stack:** NestJS 10 API and workers, BullMQ on Redis, PostgreSQL, Anthropic TypeScript SDK, Next.js 14 review app.

## Pipeline

```
POST /batches or /batches/csv (editor) → BullMQ "contentloom-generate" (jobId = itemId, 4 attempts, exponential backoff, 50/min limiter)
  worker: budget check → generate → deterministic checks + LLM judge → near-duplicates + other locales → route
    ├─ auto_approved ── publish (publisher role) → transactional outbox → signed webhooks (PIM, storefront CMS)
    └─ in_review ───── reviewer leases the draft: approve (optionally edited) | reject | revise (note → regenerate, priority 1)
```

- **Prompts** (`api/src/prompts.ts`): everything shared by a batch (instructions, locale style guide, category guidance, glossary, house examples) is in the system prompt, marked for prompt caching; per-SKU facts go in the user turn. Prompt variants can run as an experiment (`EXPERIMENT=id:control=50,benefit_led=50`), assigned by a stable hash of the SKU.
- **Scoring** (`api/src/checks.ts`, `api/src/llm.ts`) runs cheap checks first. Each check returns findings with character offsets so the review app can highlight them; `block` findings always send a draft to a person:
  - Required facts, banned claims (brief and category), length per category.
  - **Measurements** (`text/units.ts`): every size, weight or volume in the draft must match a fact, after unit conversion, allowing only for the rounding of the converted value.
  - **Claims** (`text/claims.ts`): health, safety, environmental, origin, warranty and pricing claims in all three languages, allowed only when the facts back them.
  - Hype and superlatives, typography per locale (French spacing, Spanish ¿ ¡, decimal commas, no markdown or chat preambles), glossary terms, keywords, readability (Flesch, Fernández-Huerta, Kandel-Moles).
  - An **LLM judge** with a JSON-schema structured output (`output_config.format`): rationale, accuracy, usefulness, tone. Accuracy is weighted 2×.
  - After scoring: near-duplicates of other SKUs in the batch (MinHash with LSH), and disagreement with the same SKU's copy in other locales.
- **Routing** (`api/src/domain.ts`) sends a draft to review whenever:
  - its category is regulated (baby, supplements, electrical), or an admin added it to the always-review list;
  - any fact is missing, any banned claim appears, or any check blocks;
  - the judge gave no verdict;
  - the score is under the threshold (0.85, adjustable per category at runtime);
  - **or** it lands in a random 10% QA sample of drafts that would otherwise auto-approve.

  The QA sample is what measures **auto-approve precision** (`GET /metrics`, with a Wilson 95% interval), the number that justifies the threshold. `GET /metrics/calibration` shows precision and coverage at other thresholds and recommends the lowest safe one.

- **Revisions:** a reviewer's revision note and the previous draft go back into the generation prompt, and the item re-queues at high priority.
- **Retries:** transient model errors retry through the queue's backoff. Refusals and other non-retryable errors fail at once. After the last attempt the item is marked `failed`, never silently dropped; `POST /batches/:id/retry-failed` queues them again.
- **Budget:** `DAILY_BUDGET_USD` caps spend per UTC day from the recorded token usage; work over budget is deferred to the next day, not failed.
- **Lifecycle:** an explicit state machine. Illegal transitions (publishing an unreviewed draft, reviewing an item twice) return 409. Every write is compare-and-set on the item's version.
- **Review leases:** `POST /review/claim` hands each reviewer a different draft and holds it for 15 minutes (kept alive by the app), so two people never edit the same copy. Drafts waiting longer than `REVIEW_SLA_HOURS` are flagged.
- **Roles** (from the SSO gateway): editors create batches, reviewers review, publishers publish and withdraw, admins manage the glossary, routing policy and webhooks. Batch creation is rate-limited per user.
- **Webhooks:** publish and withdraw write to an outbox; the dispatcher delivers with `t=…,v1=…` HMAC signatures, exponential backoff and a dead-letter state that admins can retry.
- **Deployment:** the API and the workers are separate processes (`main.ts`, `worker.main.ts`), so workers can scale on queue depth. Workers also run housekeeping: requeueing items a dead worker left in `generating`, clearing expired leases, flagging overdue reviews, dispatching webhooks.

## API

| Area | Endpoints |
| --- | --- |
| Batches | `POST /batches`, `POST /batches/csv`, `GET /batches`, `GET /batches/:id`, `GET /batches/:id/items?q=`, `POST /batches/:id/cancel`, `/retry-failed`, `/publish` |
| Review | `GET /review`, `GET /review/queue?q=`, `POST /review/claim`, `POST /items/:id/heartbeat`, `/release`, `/review`, `/lint` |
| Items | `GET /items?q=`, `GET /items/:id`, `GET /items/:id/view`, `POST /items/:id/publish`, `/withdraw`, `/reopen`, `/regenerate`, comments |
| Locales | `GET /skus?prefix=`, `GET /skus/:sku` (every locale of a SKU side by side, with disagreements) |
| Metrics | `GET /metrics`, `/metrics/calibration`, `/metrics/daily`, `/metrics/experiments` |
| Admin | `GET/POST/DELETE /glossary`, `POST /glossary/import`, `GET/PATCH /policy`, `GET /audit`, `GET /outbox`, `POST /outbox/:id/retry`, `POST /admin/sweep` |
| Exports | `GET /exports/published?locale=&format=csv\|jsonl`, `GET /exports/reviews` |
| System | `GET /health`, `GET /meta`, `GET /events` (Server-Sent Events) |

`q=` takes the search language, e.g. `status:in_review category:baby,electrical score<0.7 locale:fr-CA finding:claim. "pre-washed"` (see `api/src/search.ts`).

## Review app (`review/`)

- **Review:** one draft at a time, worst first, next to its facts, the reasons it was flagged and its score breakdown. Findings are highlighted in the text; edits are diffed live and re-checked before approval; keyboard shortcuts for every decision.
- **Queue, batches, search, locales:** the backlog with reasons and who holds what (live over SSE), batch progress with bulk publish and retry, a CSV upload with a row-by-row preview, search with the query language, and every SKU's locales side by side.
- **Metrics:** precision with its interval, threshold calibration, reviewer throughput and edit rates, top findings, cost per published item, prompt experiment results.
- **Glossary and admin:** terminology management with CSV import, routing policy, webhook deliveries, the audit log and exports.

## Run it

```bash
# Self-contained demo: simulated model, in-memory store, seeded with 40 SKUs in three locales.
cd api && npm install && npm run demo            # API on :3001
cd review && npm install && npm run dev          # review app on :3002

# Full stack with Postgres, Redis, a worker and the real model:
ANTHROPIC_API_KEY=... docker compose up --build

# Operations CLI against a running API:
cd api && npm run cli -- import briefs.csv --name "Spring throws" --wait
```

Configuration is read from the environment and validated at startup (`api/src/config.ts`): `DATABASE_URL`, `REDIS_HOST`, `AUTO_APPROVE_AT`, `SAMPLE_RATE`, `CATEGORY_THRESHOLDS`, `DAILY_BUDGET_USD`, `LEASE_MINUTES`, `REVIEW_SLA_HOURS`, `WEBHOOK_URLS`, `WEBHOOK_SECRET`, `EXPERIMENT`, `SCHEDULER_ENABLED`. Database changes are forward-only SQL migrations in `api/migrations` (`npm run migrate`).

## Test

```bash
cd api && npm install && npm test   # tsc + node:test: unit, store and end-to-end tests (Nest + supertest) with an in-memory queue and a fake Claude client
CONTENTLOOM_TEST_DATABASE_URL=postgres://localhost/contentloom_test npm test   # adds the Postgres store tests
cd review && npm install && npm run build
```

The tests cover:

- Auto-approve and publish, plus the request shape (model, fallbacks, prompt caching, JSON-schema judge).
- Banned-claim, regulated-category, blocking-finding and QA-sample routing, and runtime policy changes.
- Edit-and-approve with diffs, linting edited text, and revision feedback reaching the writer prompt.
- Retry, refusal and permanent failure; budget deferral; recovery of items stuck in `generating`.
- Role, lifecycle and rate-limit guards; review leases between two reviewers; overdue reviews.
- Every text check: tokenizing, readability, measurements and unit conversion, claims, typography, glossary, diffs, near-duplicates, CSV.
- Webhook signatures, retries and dead letters; exports; search; batch CSV import, cancellation and completion; cross-locale consistency.
- QA-sample precision, calibration, experiment statistics and the demo pipeline end to end.
